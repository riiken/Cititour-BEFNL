# Deploying CitiTour

About 20–30 minutes. You need three free accounts: **MongoDB Atlas**, **Render** and **GitHub** (already set up).
Production deploys from each repo's default branch: `master` (API) and `main` (web app). `rewire` is the working branch.

```
Browser / Android app ──► cititour (Render static site, Angular)
                              │  calls
                              ▼
                         cititour-befnl (Render web service, Node API) ──► MongoDB Atlas
                              │
                              └─► Gemini / Groq, Wikipedia, Wikivoyage, OpenStreetMap, OpenWeather, Unsplash
```

---

## 1. Database: MongoDB Atlas (≈ 8 min)

1. Sign in at <https://cloud.mongodb.com> → **Create** a cluster.
   - Tier: **M0 (free)** to start; move to **Flex/M10** when you have real traffic.
   - Provider/region: **AWS, Mumbai (ap-south-1)** for the lowest latency from India and Render Singapore.
   - Name: `cititour`.
2. **Database Access** → *Add new database user*
   - Username `cititour-api`, **Autogenerate secure password** → copy it somewhere safe.
   - Role: *Read and write to any database*.
3. **Network Access** → *Add IP address* → **Allow access from anywhere (0.0.0.0/0)**.
   Render's free/starter services don't have fixed IPs; the strong password protects the database.
4. **Connect** → *Drivers* → copy the connection string and set the database name `cititour`:
   ```
   mongodb+srv://cititour-api:<PASSWORD>@cititour.xxxxx.mongodb.net/cititour?retryWrites=true&w=majority
   ```

> The old cluster in `.env` (`formiq.oykocwd…`) no longer exists. Anything that was stored there is gone; the app starts with an empty database and fills its caches as people use it.

## 2. API: Render web service (≈ 8 min)

1. <https://dashboard.render.com> → **New** → **Blueprint** → connect GitHub → choose **riiken/Cititour-BEFNL**.
   Render reads `render.yaml` and proposes the `cititour-befnl` service (region Singapore, branch `master`).
2. Fill in the values it asks for:

   | Setting | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string from step 1 |
   | `ADMIN_EMAILS` | `admin@paathly.in` |
   | `FRONTEND_URL_PROD`, `APP_URL` | `https://cititour.onrender.com` (or your own domain later) |
   | `CONTACT_EMAIL` | an address Wikimedia/OSM can contact you at |
   | `GEMINI_API_KEY`, `GROQ_API_KEY` | from your local `.env` |
   | `OPENWEATHER_API_KEY`, `UNSPLASH_API_KEY` | from your local `.env` (optional) |
   | `EMAIL_HOST`, `EMAIL_USER`, `EMAIL_PASS`, `RECIPIENT_EMAIL` | your SMTP details (Gmail: use an *App password*) |
   | `BOOKING_AFFILIATE_ID`, `GYG_PARTNER_ID` | leave empty until the programmes approve you |
   | `RAPIDAPI_KEY` | leave empty (the provider is currently over quota) |

   `JWT_SECRET` and `JWT_REFRESH_SECRET` are generated by Render automatically.
3. **Apply**. The first deploy takes ~3 minutes. Check:
   - `https://cititour-befnl.onrender.com/ready` → `{"success":true,"database":"connected"}`

**Plan:** the blueprint uses **Starter (~$7/month)**. On the free plan the API sleeps after 15 minutes idle and the first visitor waits 30–60 s, which hurts conversions. Switch to free in the dashboard if you want to test first.

## 3. Web app: Render static site (≈ 5 min)

1. **New** → **Blueprint** → choose **riiken/CitiTour** → apply (service `cititour`, branch `main`).
2. When the build finishes, open `https://cititour.onrender.com`.
   The app is already configured to call `https://cititour-befnl.onrender.com` (`src/app/environment.prod.ts`).
   If you rename the API service, update that file.

## 4. First-run checklist (≈ 5 min)

- [ ] Open the site → **Plan a trip** → Udaipur → a plan appears within ~10 s.
- [ ] **Register** with `admin@paathly.in` → user menu shows **Admin**.
- [ ] **List your business** → create a test listing → you receive the "new listing" email → approve it in **Admin** → the owner email arrives → delete the test listing.
- [ ] On the trip page, tap a **Check prices** link → `npm run stats` (run locally with `MONGODB_URI` pointing at Atlas) shows the click.

## 5. Your own domain (optional)

Render → each service → **Settings → Custom domains** (e.g. `cititour.in` for the site, `api.cititour.in` for the API).
Then update `FRONTEND_URL_PROD` / `APP_URL` on the API and `apiUrl`/`apiURL`/`authURL` in `src/app/environment.prod.ts`, commit, and both redeploy automatically.

## 6. Turn on revenue

| What | Where | Then set |
|---|---|---|
| Booking.com Affiliate Partner Programme | Booking.com affiliate site (may now be via CJ Affiliate) | `BOOKING_AFFILIATE_ID` on the API |
| GetYourGuide partner programme | partner.getyourguide.com | `GYG_PARTNER_ID` on the API |
| Google AdSense (web ads) | adsense.google.com, site `cititour.onrender.com` or your domain | already wired: `adsenseClient`/`adsenseSlot` in `environment.prod.ts` |
| Featured listings | Admin page → **Feature** | charge businesses offline until online payments are added |

Affiliate links and ads start earning as soon as the IDs are set; no redeploy of the web app is needed for affiliate IDs.

## 7. Operating

- **Logs:** Render → service → *Logs* (JSON lines; no passwords or request bodies are logged).
- **AI spend:** capped at `AI_DAILY_GENERATION_LIMIT` plans/day; set `AI_ENABLED=false` to switch AI off instantly (plans still work without AI).
- **Revenue report:** `npm run stats -- 30` (clicks by partner, enquiries, top destinations).
- **Deploys:** every push to `master` (API) or `main` (web app) redeploys automatically; GitHub Actions runs the backend tests first.
